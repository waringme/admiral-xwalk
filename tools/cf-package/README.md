# Travel landing pages — content fragment package

This package holds the content shared by the SEO (`/travel-insurance`) and PPC (`/travel-insurance/generic`) landing pages. It covers the content that is the same and only laid out differently on each page. The scope is in `stardust/travel-landing-cf-scope.md`.

Build with `python3 tools/cf-package/build.py`. The output is `dist/admiral-xwalk-travel-cf-<version>.zip` (current: 1.1.0 — adds the Media Text model, the What's travel insurance? fragment and the media-text-by-path query; 1.0.2 selects SVG images as DocumentRef; 1.0.0 typed the reference fields as plain text lists, which GraphQL rejects).

| What | Where |
|---|---|
| Models | `/conf/admiral-xwalk/settings/dam/cfm/models/`: `feature`, `feature-list`, `cover-level`, `cover-levels`, `media-text` |
| Fragments | `/content/dam/admiral-xwalk/fragments/travel/`: `key-benefits`, `cover-features`, `cover-levels` (+ `features/`, `levels/`), `whats-travel-insurance` (Media Text) |
| GraphQL | endpoint `/content/cq:graphql/admiral-xwalk/endpoint`; persisted queries `admiral-xwalk/feature-list-by-path`, `admiral-xwalk/cover-levels-by-path`, `admiral-xwalk/media-text-by-path` |
| Data | `fragments/**.json` (generated from the live pages; SEO wording, PPC illustrations) |

## Install (AEM author)
1. **Images:** install `stardust/packages/admiral-xwalk-images-1.6.0.zip` first. It holds the icons and illustrations that the fragments reference.
2. **This package:** install it with Package Manager.
3. **Configuration Browser** › `admiral-xwalk`: make sure **Content Fragment Models** and **GraphQL Persistent Queries** are enabled. The package creates the folders but cannot tick those boxes on an existing configuration.
4. **Publish** the models, the fragments (with their referenced fragments and images), the GraphQL endpoint and the three persisted queries.

The package replaces the `/content/dam/admiral-xwalk/fragments/travel` folder: edits made to these fragments in AEM are overwritten when it is reinstalled.

## Delivery
- The site reads the fragments from the publish tier, `publish-p147324-e2050468`. CORS for this site's origin was verified on 2026-10-09.
- To use another publish host, set the page metadata `aem-publish-host`.
- In the Universal Editor the block reads from author, and the fragment fields are editable in place.

## Car insurance set (`python3 tools/cf-package/build.py car`)
`dist/admiral-xwalk-car-cf-1.0.0.zip` holds only what the car insurance pages add. Its filter covers new nodes only, so installing it changes nothing that is already migrated.

| What | Where |
|---|---|
| Models | `product-pod`, `product-pod-list`, `cover-tier`, `cover-row`, `cover-table`, `cover-comparison` |
| Fragments | `fragments/car/` (car insurance page) and `fragments/shared/` (product pods other product pages reuse). Each folder carries its own allowed models, including the travel Feature, Feature List and Media Text models |
| GraphQL | persisted queries `admiral-xwalk/product-pod-list-by-path`, `admiral-xwalk/cover-comparison-by-path` (the Feature List and Media Text fragments use the travel queries) |
| Data | `fragments/car/**.json`, `fragments/shared/**.json` (generated by `stardust/.work/replica/car-cf-data.py`) |

Install order: travel content fragment package 1.1.0 (models, endpoint, queries), then `stardust/packages/admiral-xwalk-car-images-1.0.0.zip`, then this package. Publish the new models, the `car` and `shared` folders and the two new queries.

The cover comparison is three layers, so a tier or row is edited once:
- **Cover Tier**: name + logo, one per tier (Platinum, Gold, Admiral, Essential, Third party fire & theft, Third party only).
- **Cover Row**: one benefit with a value per tier: `yes` (tick), `x` or empty (cross), or text (`Up to £300`, `Optional`).
- **Cover Table**: one tab, listing its tiers (columns) and rows. **Cover Comparison** lists the tabs, with a heading, introduction and footnote.
